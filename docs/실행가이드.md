# 알바지킴이 실행 가이드

명령마다 쓰는 인자의 뜻, `.env` 설정값, 자주 겪은 문제와 해결 방법을 모았다.
명령은 Mac 터미널 기준이다. `프로젝트 폴더`는 `GyeongnamAI-SWCompetition` 폴더를 말한다.
Windows(PowerShell)에서는 `.venv/bin/python`을 `.venv\Scripts\python.exe`로, `source .venv/bin/activate`를 `.venv\Scripts\activate`로 바꿔 쓴다
(예: `.venv\Scripts\python.exe -m uvicorn app.main:app --port 8080`). `cp -n .env.example .env`는 `if (!(Test-Path .env)) { Copy-Item .env.example .env }`.

## 0. 먼저 확인할 것 (실수가 가장 많았던 것)

1. **코드를 받았는가**: 수정이 main에 합쳐져도 내 컴퓨터의 코드는 그대로다. `git pull origin main`을 해야 바뀐다 (2절).
2. **최신 코드로 켜졌는가**: 서버 로그에 `알바지킴이 코드 버전`, `저장 위치` 두 줄이 보여야 한다. 없으면 예전 코드다.
3. **`.env`를 고친 뒤 서버를 다시 켰는가**: `--reload`도 `.env` 변경은 감지하지 않는다.
4. **어느 데이터로 켜졌는가**: 로그의 `저장 위치`가 `data/app.db`면 평소 데이터, `data/test/app.db`면 시험 데이터다 (3-1절).
5. **외부에 열기 전**: `SECRET_KEY` 바꾸기, 실제 AI 모델 연결 확인(안 하면 가짜 AI가 "테스트 답변입니다"로 답함), `DEV_TOOLS=false`, 시연 데이터는 가상 정보만.
6. **고친 뒤 다른 기능이 깨지지 않았는가**: main에 합치기 전에 `pytest`를 통과해야 하고, 화면을 바꿨으면 그 화면의 파트(`bash tests/ui/run_all.sh part15`처럼)도 통과해야 한다 (5절). 전체 화면 시험은 돌리지 않는다. 서버 로그에 `Traceback`이나 `raised an exception`이 보이면 화면이 멀쩡해도 고장이다.

## 1. 처음 한 번: 라이브러리 세팅

```bash
cd 프로젝트 폴더
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
cp -n .env.example .env
```

| 명령 / 인자 | 뜻 |
|---|---|
| `python3 -m venv .venv` | 이 프로젝트만 쓰는 파이썬 환경을 `.venv` 폴더에 만든다. 다른 프로젝트의 라이브러리와 섞이지 않는다 |
| `source .venv/bin/activate` | 그 환경을 켠다. 터미널 앞에 `(.venv)`가 붙는다. 새 터미널을 열 때마다 다시 한다 |
| `-m pip` | 지금 켜진 파이썬에 딸린 pip을 쓴다 (다른 파이썬에 설치되는 실수 방지) |
| `--upgrade pip` | pip 자체를 최신으로 올린다 |
| `-r requirements.txt` | 파일에 적힌 라이브러리를 한꺼번에 설치한다 |
| `cp -n` | `.env`가 이미 있으면 덮어쓰지 않는다. `-n` 없이 다시 하면 채워 둔 키가 모두 지워진다 |

## 2. 최신 코드 받기 (수정이 반영 안 된 것 같으면 제일 먼저)

```bash
git checkout main
git pull origin main
pip install -r requirements.txt
```

| 인자 | 뜻 |
|---|---|
| `checkout main` | main 브랜치로 옮긴다. `claude/...` 작업 브랜치는 매번 main에 맞춰 다시 올리므로 거기서 pull하면 충돌한다 |
| `pull origin main` | GitHub(origin)의 main 변경을 받아 합친다 |
| 다시 `pip install -r` | 새로 추가된 라이브러리가 있을 수 있다 |

최신 코드인지 확인: 서버를 켜면 로그에 아래 두 줄이 나온다. 커밋 번호는 GitHub main의 마지막 커밋과 같아야 한다.
브라우저에서 `주소/api/version`을 열어도 볼 수 있다.

```
INFO:     알바지킴이 코드 버전: <커밋 번호> <날짜>
INFO:     저장 위치: 기록 …/data/app.db, 증거 원본 …/data/uploads, 상담 사전 자료 …/data/reports
```

로그 수준을 낮추는 옵션(`--log-level warning` 등)을 붙이면 이 두 줄도 보이지 않는다.

## 3. 서버 실행 (개발, 테스트용)

```bash
source .venv/bin/activate
uvicorn app.main:app --reload
```

| 인자 | 뜻 |
|---|---|
| `app.main:app` | `app/main.py` 안의 `app` 변수(FastAPI 앱)를 실행한다 |
| `--reload` | 코드 파일이 바뀌면 서버가 다시 켜진다. 개발용이라 외부에 열 때는 뺀다. `.env` 변경은 감지하지 않는다 |
| `--port 8080` | 접속 번호. 기본은 8000인데 GPU 서버에서는 vLLM이 8000을 쓰므로 8080을 쓴다 |
| `--host 0.0.0.0` | 기본(`127.0.0.1`)은 이 컴퓨터에서만 접속된다. `0.0.0.0`은 같은 와이파이의 다른 기기에서도 접속되게 한다 |

## 3-1. 시험 데이터 / 평소 데이터로 실행

| | 평소 데이터 | 시험 데이터 |
|---|---|---|
| 정하는 법 | `TEST_DATA=false` (또는 줄 없음) | `TEST_DATA=true` |
| 기록(DB) | `data/app.db` | `data/test/app.db` |
| 올린 파일 | `data/uploads` | `data/test/uploads` |
| 상담 자료 | `data/reports` | `data/test/reports` |
| 로그인 | 내가 가입한 계정 | `test@example.com`, `test2~5@example.com` / `test1234` |

`.env`의 `TEST_DATA` 줄로 정하거나, 서버 켜는 명령 앞에 붙인다 (명령에 붙인 값이 먼저). 6절의 실행 명령이라면 `.venv/bin/uvicorn` 앞에 `TEST_DATA=true `를 넣는다.
켜진 뒤에는 로그로 확인한다: 시험 데이터면 `저장 위치: 기록 …/data/test/app.db`와 '시험 데이터로 실행 중이에요'가 보인다.

**시험 데이터는 따로 만들지 않아도 된다.** `data/test`가 없으면 서버가 켜지면서 만들고, 있으면 그대로 쓴다.
계정 5개(모두 홍길동, 2009-05-20생, 만 17세)는 **방금 가입한 처음 이용자**다: 일하는 곳, 출퇴근 기록, 사진이 없고 체험 안내가 켜져 있다. 로그인하면 시작 화면에서 상황(구하는 중/일하는 중/그만둠)을 고르고 체험 미션을 한다. 사진은 시연 때 `DEMO_MODE=true`로 업로드 화면에서 데모 자료를 골라 올린다. 한 번 시연하면 진행한 상태가 남으니, 다시 처음 상태로 하려면 아래처럼 되돌린다.

**알바 5개 사례가 든 계정** (정답지 확인, 기기 크기 화면 캡처용): `.venv/bin/python -m app.demo_db --scenarios --force`. 행복편의점(테스트자료 원본 시나리오), 가상분식(적게 받음), 가상카페(모두 정상), 가상베이커리(정보 부족), 가상치킨(그만두고 못 받음, 신고 후 보호)의 사업장 정보와 출퇴근 기록이 들어간다 (사진과 받은 금액은 넣지 않음, 체험 안내 없음).

**처음 상태로 되돌리기** (서버를 끄고): `.venv/bin/python -m app.demo_db --force`
`data/test`만 지우고 다시 만든다 (`--scenarios`를 붙이면 알바마다 만든 내용, 코드가 계산한 금액, 기대 결과를 출력). `--force` 없이는 "이미 있어요" 하고 멈춘다.

**법 기준표**: 시험 데이터를 만들 때 평소 DB의 법 기준표를 읽기만 해서 복사한다 (출력 첫 줄 `법 기준표: 평소 DB에서 N건 복사`). 없으면 에이전트가 조문을 확인하지 못한다 ('법 기준표 미구축'). '복사하지 못했어요'가 나오면 시험 DB에 직접 만든다 (`LAW_OC` 필요): `TEST_DATA=true .venv/bin/python -m app.law.fetch`

주의할 점 (실제로 겪은 것):
- 명령이나 `.env`에 `DB_PATH`, `UPLOAD_DIR`, `REPORT_DIR`를 적지 않는다. 그 값이 `TEST_DATA`보다 먼저 적용돼 기록과 파일이 다른 폴더에 섞인다.
- `TEST_DATA`는 `.env.example`이 아니라 `.env`에 적고, 줄은 하나만 둔다 (같은 줄이 둘이면 맨 앞만 쓴다). `grep -n TEST_DATA .env`로 확인한다.
- 예전의 `data/demo.db`는 더 쓰지 않는다: `rm -f data/demo.db`

## 4. `.env` 설정값

`.env`를 고친 뒤에는 서버를 껐다 켠다. `.env`는 GitHub에 올리지 않는다.

### 보안
| 키 | 기본값 | 설명 |
|---|---|---|
| `SECRET_KEY` | `dev-secret-change-me` (`.env.example`은 `change-me`) | 로그인 쿠키에 서명하는 비밀키. 기본값이면 쿠키를 위조당할 수 있다. 만들기: `python -c "import secrets; print(secrets.token_hex(32))"` |
| `LOGIN_MAX_FAILS` | 5 | 같은 이메일로 이만큼 틀리면 막는다 |
| `LOGIN_IP_MAX_FAILS` | 20 | 같은 접속 주소에서 이만큼 틀리면 막는다 (여러 계정에 번갈아 넣는 것 방지) |
| `LOGIN_LOCK_MIN` | 15 | 막는 시간(분) |

### AI 모델
| 키 | 기본값 | 설명 |
|---|---|---|
| `LLM_ENABLED` | false | `true`면 AI가 판단, 작성, 사진 읽기를 한다. `LLM_MODEL`도 있어야 켜진다 |
| `LLM_BASE_URL` | `http://localhost:8000/v1` | vLLM 주소. 끝에 `/v1`까지 적는다 |
| `LLM_MODEL` | (없음) | `vllm serve`에 쓴 모델 이름. 모르면 `curl <주소>/v1/models` 결과의 `id` |
| `LLM_VISION_MODEL` | (없음) | 사진 읽기용 모델. 비우면 `LLM_MODEL`을 쓴다 |
| `LLM_API_KEY` | (없음) | `vllm serve --api-key`로 키를 걸었을 때만 |
| `LLM_TIMEOUT` | 120 | AI 호출 한 번을 기다리는 최대 시간(초). 넘으면 'AI 응답 대기 중'으로 두고 나중에 다시 맡긴다 |
| `LLM_MAX_TOKENS` | 4096 | AI 답 하나의 최대 길이(토큰). 모델이 같은 말을 되풀이해도 요청이 몇 분씩 걸리지 않게 한다. 0이면 제한 없음 |
| `LLM_EXTRA_BODY` | (없음) | 모델마다 필요한 요청 옵션(JSON). 예: 생각 모드 끄기 `{"chat_template_kwargs": {"enable_thinking": false}}`. 모델별 값은 `bench/models.json`의 `extra_body` |
| `AGENT_MAX_STEPS` | 30 | 에이전트 판단 반복 최대 횟수(3~50). 이 안에 끝내지 못하면 'AI 응답 대기 중'으로 둔다. AI 버튼은 서버가 뒤에서 실행하고 화면이 결과를 따로 물어서, 오래 걸려도 cloudflared 한도(100초)에 끊기지 않는다 |
| `LLM_SAMPLING` | (없음) | 모델 공식 문서의 권장 생성 설정(JSON). 비우면 temperature 0. `null`은 모델 기본값을 쓴다. 모델별 값은 `bench/models.json`의 `sampling` |
| `LLM_FAKE` | auto | 가짜 AI. `auto`: 실제 모델 설정(`LLM_ENABLED=true`와 `LLM_MODEL`)이 없으면 가짜 AI가 `테스트 답변입니다 (…)`로 답한다. `true`: 늘 가짜 AI. `false`: 가짜 AI 없이 'AI 응답 대기 중'(도는 로딩 표시)으로 둔다 |
| `LLM_FAKE_DELAY` | 3 | 가짜 AI가 요청을 받고 답하기까지 기다리는 시간(초). 한 번 점검에 AI를 여러 번 부르므로 점검 하나가 수십 초 걸릴 수 있다. 빨리 확인하려면 0 |
| `AI_RETRY_MIN` | 10 | 'AI 응답 대기 중'인 일을 몇 분마다 다시 맡길지 (AI가 있을 때만. 가짜 AI도 포함). 예약한 확인도 이 간격으로 본다 |
| `AI_RETRY_PER_DAY` | 3 | 같은 일을 하루 최대 몇 번 다시 맡길지 |

연결 확인: `python -m app.llm.probe`. 도구 호출이 안 된다고 나오면 vLLM을 켤 때
`--enable-auto-tool-choice --tool-call-parser <모델에 맞는 파서>`가 필요하다. (vLLM 서버는 이 프로젝트에서 끄거나 다시 켜지 않는다.)

### 체험 안내, 설문, 데모 모드
| 키 | 기본값 | 설명 |
|---|---|---|
| `FIRST_GUIDE` | true | 새로 가입한 계정에 처음 쓰는 사람 체험 안내(통합 미션 8개, 예시 자료, 설문)를 보여 준다. 화면 회귀 시험은 false로 돈다 |
| `SURVEY_URL` | 구글폼 주소 | 체험을 마치면, 그리고 일하는 곳 선택 창에서 늘 보여 주는 설문 주소. 비우면 설문 안내가 없다 (예전 이름 `BETA_FORM_URL`도 읽는다) |
| `DEMO_MODE` | false | 모든 계정의 업로드(채용공고, 근로계약서, 명세서, 자료 올리기)를 누르면 '내 기기에서 고르기'와 데모 자료 30장(`테스트자료/`, 알바 5곳마다 채용공고, 계약서, 근무표, 명세서, 입금 내역, 사장님 메시지)을 함께 보여 준다. 채용공고를 고르면 그 가게 조건으로 공고 칸을 채운다. 그 칸에 맞는 자료가 먼저 나오고, 일하는 곳 등록 화면에 '이 예시로 채우기'도 늘 보인다. 실제 업로드와 사진 읽기(AI) 시연용 |

**처음 쓰는 사람 체험 안내**: 새로 가입한 계정에만 보여 준다. 시험 계정(test@ 등)도 처음 이용자로 만들어 안내가 뜬다 (`--scenarios`로 만든 계정과 예전부터 있던 계정에는 뜨지 않는다).
- 가입하면 첫 안내 창: 고른 상황과 상관없이 모든 새 계정에 같은 미션 8개 (세 상황의 미션을 합친 것, 테스터가 핵심 기능을 모두 써 보고 설문하게). '안내 없이 쓸게요'로 끌 수 있다.
- 미션 8개: 지원 전 확인 → 일할 곳 등록 → 출근·퇴근 → 계약서 사진으로 점검 → 받은 급여 올리고 비교 → 그만둔 곳 등록 → 남은 임금 받았는지 답하기 → 상담 사전 자료. 일하는 중으로 등록한 곳은 홈의 '이곳을 그만뒀어요'로 그만둔 곳이 된다.
- 시작 화면(상황 고르기)과 기본 정보 화면에서는 안내 창을 띄우지 않는다 (상황을 고르기 전에 가입된 시험 계정도 상황을 고른 뒤에 안내).

- 화면 오른쪽 아래 '체험 미션 n/8' 버튼: 미션마다 누를 버튼 순서와 '바로 가기', '체험 안내 끄기'. 미션은 서버가 기록으로 판정한다 (가입한 뒤에 한 일만).
- 체험하는 동안 업로드를 누르면 '내 기기에서 고르기'와 예시 자료(테스트자료의 가상 가게)를 함께 보여 준다. 예시 채용공고나 계약서를 고르면 칸을 채워 준다. 다 끝낸 뒤에는 업로드가 바로 내 파일 고르기다.
- 미션 8개를 다 하면 '설문하기 / 계속 쓰기' 창. 설문은 일하는 곳 선택 창의 '써 보니 어떤가요? 설문하기'에도 늘 있다 (`SURVEY_URL`, 비우면 숨김).
- 예전 베타 체험판 계정(beta1~9, owner1~3)이 DB에 남아 있으면 지운다 (다른 계정은 그대로):
```bash
.venv/bin/python -m app.guide --remove-old-beta          # 리눅스, macOS
```

## 6. 어디서나 접속 (cloudflared)

설치 (처음 한 번만):

```bash
mkdir -p ~/tools && cd ~/tools
curl -L -o cloudflared.tgz https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-darwin-arm64.tgz
tar -xzf cloudflared.tgz
./cloudflared --version
```

| 인자 | 뜻 |
|---|---|
| `mkdir -p` | 폴더가 이미 있어도 오류 없이 넘어간다 |
| `curl -L` | 주소가 다른 곳으로 넘겨져도 따라가서 받는다 |
| `-o cloudflared.tgz` | 받은 파일 이름 |
| `darwin-arm64` | M1/M2/M3 Mac용. 인텔 Mac이면 `darwin-amd64` |
| `tar -xzf` | 압축 풀기 (x 풀기, z gzip, f 파일 이름) |

실행 (매번, 아무 폴더에서나):

```bash
( P=$(mdfind -onlyin ~ 'kMDItemFSName == "GyeongnamAI-SWCompetition" && kMDItemContentType == "public.folder"' | head -1); [ -d "$P" ] || P=$(find ~ -maxdepth 4 -type d -name GyeongnamAI-SWCompetition 2>/dev/null | head -1); cd "$P" || exit 1; .venv/bin/uvicorn app.main:app --port 8080 & UV=$!; trap "kill $UV 2>/dev/null; exit" INT TERM; trap "kill $UV 2>/dev/null" EXIT; sleep 2; ~/tools/cloudflared tunnel --protocol http2 --url http://127.0.0.1:8080 )
```

| 부분 | 뜻 |
|---|---|
| 전체를 감싼 `( … )` | 따로 떨어진 셸에서 실행한다. 안에서 `cd`해도 지금 터미널 위치는 그대로다 |
| `mdfind -onlyin ~ '…'` | Spotlight로 홈 폴더에서 이름이 `GyeongnamAI-SWCompetition`인 폴더를 찾는다 |
| `head -1` | 찾은 것 중 첫 번째만 쓴다 |
| `[ -d "$P" ] \|\| P=$(find …)` | Spotlight가 못 찾으면 `find`로 다시 찾는다 |
| `find -maxdepth 4 -type d -name …` | 홈에서 4단계 깊이까지, 폴더 중 그 이름을 찾는다 |
| `2>/dev/null` | 권한 없음 같은 오류 메시지를 숨긴다 |
| `cd "$P" \|\| exit 1` | 폴더로 가고, 못 가면 멈춘다 |
| `.venv/bin/uvicorn` | 가상환경을 켜지 않아도 그 안의 uvicorn을 쓴다 |
| `--port 8080` | vLLM(8000)과 겹치지 않게. `--reload`는 외부용이라 뺐다 |
| `&` 와 `UV=$!` | 서버를 뒤에서 돌리고 프로세스 번호를 `UV`에 기억한다 |
| `trap "…" INT TERM` | Ctrl+C로 끄면 서버도 같이 끄고 나간다 |
| `trap "…" EXIT` | 어떤 이유로 끝나도 서버를 남기지 않는다 |
| `sleep 2` | 서버가 켜질 때까지 기다린다 |
| `tunnel --url` | 계정 없이 쓰는 임시 터널. 주소(`…trycloudflare.com`)는 켤 때마다 바뀐다 |
| `--protocol http2` | 기본 방식(QUIC, UDP)이 막힌 와이파이에서도 연결되게 한다 |
| `127.0.0.1` | `localhost`로 적으면 IPv6(`::1`)로 연결해 "connection refused"가 난다 |

접속은 로그에 나온 `https://…trycloudflare.com`. 로그에서 `알바지킴이 코드 버전`, `저장 위치` 줄로 최신 코드인지 확인한다.

외부에 열기 전 확인:
1. `SECRET_KEY`를 무작위 값으로 바꿨다
2. 실제 AI 모델이 연결됐다 (`python -m app.llm.probe`. 안 되면 가짜 AI가 답한다)
3. `DEV_TOOLS=false` (줄이 없어도 꺼져 있다)
4. 시연 데이터는 가상 정보만 (누구나 가입할 수 있다)

매일 자동 점검은 설정과 상관없이 매일 `SCHEDULE_HOUR`시(기본 9시)에 돌고 알림을 보낸다. 시연 때 그 시각을 기다리지 않고 바로 보여 주려면 내 Mac에서만 `DEV_TOOLS=true`로 켜고 서버를 다시 켠 뒤 `/api/dev/daily-check`를 부른다 (로그인한 브라우저 개발자 도구에서 `fetch("/api/dev/daily-check",{method:"POST"})`).

## 7. 같은 와이파이에서만 접속

```bash
.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8080
ipconfig getifaddr en0
```

| 인자 | 뜻 |
|---|---|
| `--host 0.0.0.0` | 같은 네트워크의 다른 기기(휴대폰 등)에서 접속되게 한다 |
| `ipconfig getifaddr en0` | Mac의 와이파이(`en0`) 내부 주소 (예: 192.168.0.92). 아무것도 안 나오면 `en1` |

접속은 `http://맥주소:8080`. 안 되면 Mac 방화벽(시스템 설정 → 네트워크 → 방화벽)을 확인한다.
이 방식은 https가 아니라서 휴대폰의 위치 기록이 동작하지 않는다 (8절).

## 8. 자주 겪은 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| 고쳤다는데 화면이 그대로다 (예: 이메일 "12"가 넘어감) | 내 컴퓨터가 예전 코드 | 2절 `git pull origin main` 후 서버 다시 켜기, 로그의 코드 버전 확인 |
| 로그에 `저장 위치` 줄이 없다 | 예전 코드이거나 로그 수준을 낮춤 | 2절, `--log-level` 옵션 빼기 |
| 결과가 모두 'AI 응답 대기 중' | `LLM_FAKE=false`인데 모델 설정이 비었거나, 모델 서버가 응답하지 않음 | 4절 AI 모델 설정 후 서버 다시 켜기, `python -m app.llm.probe`. 모델 없이 흐름만 보려면 `LLM_FAKE=auto` |
| AI 글이 모두 "테스트 답변입니다" | 가짜 AI가 답하는 중 (실제 모델 설정이 없거나 `LLM_FAKE=true`) | 4절 AI 모델 설정(`LLM_ENABLED=true`, `LLM_MODEL`)을 채우고 서버 다시 켜기 |
| 로그에 `Job "retry_waiting ..." raised an exception` 같은 Traceback | 예약 작업(매일 점검, 다시 맡기기 등)에서 오류. 화면에는 안 보일 수 있다 | 최신 코드 받기(2절). 계속 나오면 Traceback 전체를 개발 대화에 붙여 넣는다. 고친 뒤 `pytest -q tests/test_regression.py` |
| "응답이 너무 오래 걸려 연결이 끊겼어요" | cloudflared는 100초 넘는 응답을 끊는다 (Cloudflare 고정값, 무료 요금제에서 못 바꿈). AI 버튼은 뒤에서 실행해 걸리지 않지만, 예전 코드면 생긴다 | `git pull origin main`으로 최신 코드 받기. 작업은 서버에서 계속되니 잠시 뒤 새로고침 |
| "작업을 찾지 못했어요" | AI 버튼 작업 중에 서버가 다시 켜짐 (뒤에서 하던 작업의 결과는 서버 메모리에만 있음) | 버튼을 다시 누른다. 에이전트가 이미 저장한 판단은 남아 있다 |
| "처리 중 오류가 났어요 (오류 번호 abc123)" | 서버 오류 | 서버 로그에서 같은 번호를 찾아 앞뒤 기록을 확인 |
| cloudflared `connection refused [::1]:8080` | 주소를 `localhost`로 적음 | `http://127.0.0.1:8080` |
| cloudflared가 연결을 못 한다, `failed to dial` | 와이파이가 QUIC(UDP)을 막음 | `--protocol http2` |
| cloudflared 로그에 `Retrying connection`, `Registered tunnel connection` | 연결이 잠깐 끊겼다가 다시 붙음 | 정상. 계속 반복될 때만 네트워크 확인 |
| `address already in use` | 8080을 이미 다른 서버가 씀 (예전에 켠 서버가 남음) | `lsof -i :8080`으로 번호(PID)를 확인하고, 어떤 서버인지 본 뒤 `kill PID`. 8000번(vLLM)은 건드리지 않는다 |
| 휴대폰(사파리)에서 위치 기록이 안 된다 | 브라우저는 https 주소에서만 위치를 준다 | cloudflared 주소(https)로 접속, 휴대폰 설정에서 사파리 위치 권한 허용 |
| 사이트에 연결할 수 없다 (같은 와이파이) | 서버가 꺼졌거나 `--host 0.0.0.0` 없음, 방화벽 | 7절 |
| 게시물 보존 때 "화면 캡처는 못 했어요" | 서버 컴퓨터에 Playwright가 없거나 게시물이 열리지 않음 | 5절 playwright 설치. 주소와 확인 시각은 남는다 |
