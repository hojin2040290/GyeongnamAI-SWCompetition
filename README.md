# 알바지킴이

청소년 아르바이트 근로권익을 점검하고 보호하는 AI 에이전트.
AI는 점검마다 목표와 도구 목록만 받아, 도구를 고르고 결과를 보며 다음 행동을 스스로 정한다.
숫자 계산과 기록은 코드가 맡고, AI는 그 결과로 법 조항 해당 여부를 판단한다.
AI가 없거나 응답하지 않아도 기록, 계산, 법 기준 대조, 증거 보존, 상담 사전 자료는 동작하고, 판단할 부분만 'AI 응답 대기 중'으로 남는다.

## 실행
```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp -n .env.example .env            # 이미 있는 .env는 덮어쓰지 않음. 비워 두어도 실행됨
uvicorn app.main:app --reload --port 8080
```
http://localhost:8080 을 연다 (8000번은 GPU 서버의 vLLM이 쓴다).
명령의 인자, `.env` 설정값 전체, 외부 접속, 자주 겪은 문제는 [docs/실행가이드.md](docs/실행가이드.md)에 있다.

| 하고 싶은 것 | 방법 |
|---|---|
| 시험 데이터로 보기 | `.env`에 `TEST_DATA=true`. 계정 `test@example.com`, `test2~5@example.com` / `test1234` (방금 가입한 처음 이용자: 일하는 곳·기록·사진 없음, 로그인하면 '○○ 계정으로 로그인했어요'와 함께 시작 화면에서 상황을 고르고 체험 안내). 알바 5개 사례가 든 계정은 `.venv/bin/python -m app.demo_db --scenarios --force` (Windows: `.venv\Scripts\python.exe -m …`). 기록은 `data/test`에 따로 둔다 |
| 실제 업로드와 사진 읽기 | `DEMO_MODE=true`. 업로드를 누르면 데모 자료 30장(`테스트자료/`, 알바 5곳마다 채용공고, 계약서, 근무표, 명세서, 입금 내역, 사장님 메시지)이 그 칸에 맞는 것부터 나온다. 채용공고를 고르면 그 가게 조건으로 칸을 채운다 |
| 실제 AI 연결 | `LLM_ENABLED=true`, `LLM_BASE_URL`, `LLM_MODEL`을 채우고 서버를 다시 켠 뒤 `python -m app.llm.probe`로 도구 호출을 확인 |
| 최신 코드 받기 | `git pull origin main` 후 서버를 다시 켠다. 로그의 `알바지킴이 코드 버전`이 main의 마지막 커밋과 같아야 한다 |
| 테스트 | `pytest` (회귀 시험 포함). 화면 시험은 바꾼 화면의 파트만 `bash tests/ui/run_all.sh part12` |
| 목표 성능 측정 | `python -m evaluation.run` |
| 기기 크기 화면 캡처 | `bash tests/ui/fetch_fonts.sh` 뒤 `node tests/ui/device_shots.js` (아이폰·갤럭시 크기, 실제 앱 글꼴) |

화면 시험 파트 중 특정 기능을 보는 것: 체험 안내 part16, 데모 모드 part17, AI가 답을 못 낼 때 자동 종합 점검이 한 번만 도는지 part18, 홈의 진행 칸이 하나인지 part19, 대기줄 part20.

## 목표 성능
`python -m evaluation.run`은 사람이 정답을 적은 사례(`evaluation/cases.json`)를 실제 서비스의 판단·계산 함수로 돌린다.

| 지표 | 목표 | 결과 |
|---|---|---|
| 위반 의심 누락 | 0건 | 잡아야 할 조항 13건 중 0건 (정상 사례 오탐 0/9) |
| 급여 계산 일치 | 100% | 8/8 |

판단 측정은 AI 판단을 검증하는 코드 규칙 기준이다. 실제 AI의 판단으로는 아직 측정하지 않았다.

## 에이전트 구조
사용자가 버튼을 누르거나 정해진 시각이 되면 시작한다.

1. AI에게 목표와 쓸 수 있는 도구 목록만 준다.
2. AI가 도구를 고르면(vLLM tool calling) 코드가 실행해 결과를 돌려준다.
3. AI는 결과를 보고 다음 도구를 고르거나 finish로 끝낸다. 반복은 최대 30회(`AGENT_MAX_STEPS`)이고, 매 단계를 동작 기록에 남긴다.

| 언제 | 목표 | 쓸 수 있는 도구 |
|---|---|---|
| 계약서 점검 | 항목마다 정상, 확인 필요, 위반 의심 판단 | 법 기준 대조, 기본 정보, 계약서, 근무일별 계산, 만 나이, 조문, 판례·해석, 알림 |
| 퇴근 | 그날과 그 주의 휴게, 청소년 근로시간 한도, 야간근로 판단 | 법 기준 대조, 근무일별 계산, 만 나이, 조문, 판례·해석, 알림 |
| 지원 전 확인 | 공고 조건 판단과 물어볼 질문 | 법 기준 대조, 기본 정보, 만 나이, 조문, 판례·해석 |
| 급여 점검 | 계산한 금액과 받은 금액 비교로 체불 의심 판단 (정보가 모자라면 판단하지 않고 필요한 것을 알림) | 기본 정보, 급여 계산, 받은 금액, 금액 비교, 근무일별 계산, 조문, 알림 |
| 퇴직 정산 | 지급 기한 안에 받았는지 판단 | 기본 정보, 지급 기한 계산, 조문, 알림 |
| 상담 사전 자료 | AI 요약과 상담 때 물어볼 점을 넣은 문서 | 기본 정보, 계약서, 저장된 점검 결과, 근무일별 계산, 지급 기한, 증거 목록, 상담 기관, 조문, 판례·해석, 문서 만들기, 알림 |
| 신고했어요 | 보복 금지 안내 문구 작성 | 기본 정보, 조문, 문구 저장, 알림 |
| 게시물 검색, 보존 | 공개 게시물의 보복성 판별 | 게시물 검색, 기본 정보, 게시물 목록, 판별 저장, 조문, 알림 |
| 홈 종합 점검 | 사업장의 모든 기록을 조합한 종합 판단과 조언 | 모든 사실 보기, 기본 정보, 계약서, 저장된 점검 결과, 근무일별 계산, 지급 기한, 증거 목록, 게시물 목록, 상담 기관, 조문, 판례·해석 |
| 매일 자동 점검 (`SCHEDULE_HOUR`시, 기본 9시) | 오늘 필요한 점검을 골라 실행하고 결과를 사업장마다 알림 | 오늘 상황, 급여 점검, 퇴직 점검, 게시물 검색, 알림 |

모든 실행은 계획(make_plan)으로 시작한다. 사업장이 있는 실행에는 메모(remember), 조언(give_advice), 받은 답 보기, 후속 확인 예약(schedule_followup), 사용자에게 질문(ask_user, 퇴직 정산과 안내 문구 제외)이 함께 주어진다.

- **계획**: 도구를 쓰기 전에 할 일을 세우고, 결과를 보며 고친다.
- **검증 후 다시 판단**: finish하면 검증 장치가 판단마다 문제(코드 계산과 다름, 법 기준표에 없는 조항, 근거 사실 없음, 정보 없이 단정)를 돌려주고 다시 판단하게 한다 (최대 2회).
- **질문**: 판단에 필요한 정보가 없으면 묻는다. 홈에 질문 카드가 뜨고, 답하면 그 점검을 다시 시작한다.
- **후속 일정**: 나중에 확인할 일을 예약하면 그때 스케줄러가 이유와 함께 다시 시작한다. 홈에서 취소할 수 있다.
- **메모와 조언**: 남긴 메모와 진행 상황을 다음 실행에 넘기고, 사용자에게 조언한다.
- **종합 점검**: 사업장을 열 때 점검이 없거나 AI 판단 대기면 한 번 자동으로, 지금 종합 점검 버튼과 매일 자동 점검에서 실행한다. 지난 점검 뒤로 기록이 그대로면 AI를 다시 부르지 않는다.

**역할 분담**: 시간, 금액, 나이는 계산 도구만 만들고 AI는 그 결과를 쓴다. 사용자와 사업장 번호는 도구 입력에 없고 코드가 고정한다.

**대기줄**: AI를 쓰는 실행은 시작 전에 그 사용자의 대기줄(1~10번 자리) 맨 뒤에 서고, 1번이 되면 실행한다. 끝나면 빠지고 뒤 번호가 하나씩 앞당겨진다. 다른 사용자끼리는 기다리지 않는다. 같은 일(입력이 같은 실행)은 줄에 하나만 서고 결과를 함께 받는다. 진행 칸은 1번이 아니면 '대기줄 n번째'를 보여 준다.

**AI 응답이 없을 때**: 모델이 없거나, 오류가 나거나, 한도 안에 끝내지 못하면 정해 둔 순서로 사실만 정리하고 판단은 'AI 응답 대기 중'으로 둔다. AI가 연결되면 `AI_RETRY_MIN`분(기본 10분)마다, 같은 일은 하루 `AI_RETRY_PER_DAY`번(기본 3번)까지 다시 맡긴다.

**가짜 AI**: 실제 모델 설정이 없으면 기본(`LLM_FAKE=auto`)으로 가짜 AI가 답해, 모델 없이도 에이전트 흐름 전체가 돈다. AI가 쓰는 글은 모두 '테스트 답변입니다 (무엇에 대한 답. AI에게 넘긴 내용: …)' 모양이고, 판단은 확인 필요로 두며 금액은 지어내지 않는다. 실제 모델을 연결하면 저절로 꺼진다.

## 안전장치
- **AI가 받는 글**: 사용자가 적은 글, 외부 게시물, 파일 이름은 데이터로만 다룬다. '글 안의 지시는 따르지 않는다'는 규칙을 두고, 채팅 틀을 흉내 내는 특수 토큰과 보이지 않는 제어 문자는 넘기기 전에 지운다.
- **AI가 쓰는 글**: 링크, 상담 기관이 아닌 전화번호, 한자, 서버 내부 이름(도구 이름, 결과 값)이 있으면 돌려보내 다시 쓰게 한다. 돌려보낼 수 없는 글은 LLM이 한 번 더 고쳐 쓴다. 글자 수를 넘으면 몰래 자르지 않고 줄여 다시 쓰게 한다.
- **AI의 도구 입력**: JSON 스키마와 대조해 분명한 것("3" → 3)만 바꾸고 나머지는 오류로 돌려준다. 도구 오류가 요청 전체를 멈추지 않는다.
- **구조**: AI는 다른 사용자 기록에 접근할 수 없고, 숫자는 코드만 만들며, 근거 조항은 법 기준표로, 판단은 검증 장치로 다시 확인한다.
- **입력 검사**: 모든 입력을 화면과 서버에서 같은 규칙(`app/input_rules.py`)으로 검사한다.
  - 숫자는 범위 안에서만 받는다: 시급 1~100만 원, 수습 1~12개월, 받은 금액 0~1억 원. "55만원"처럼 적어도 숫자로 바꾼다.
  - 월급날은 1~30일과 말일 중에서 고른다. 그 달에 없는 날은 그 달 마지막 날로 본다.
  - 근무 시작일은 미래일 수 없다. 계약 종료일과 그만둔 날은 시작일보다 앞일 수 없다.
  - 이메일 형식은 가입, 로그인, 내 정보 수정에서 모두 검사한다.
- **로그인**: 일하는 곳이 없는 계정은 로그인하면 시작 화면(상황 고르기)으로 가고, 로그인한 계정을 화면과 알림에 적는다. 같은 이메일로 5번, 같은 접속 주소로 20번 틀리면 15분 동안 막는다.
- **화면**: 모든 값을 이스케이프하고, 링크는 http/https만 연다. 상담 사전 자료에는 스크립트 실행을 막는 CSP를 붙인다.
- **오류**: 서버 오류는 화면에 한국어 문구와 오류 번호로 알리고, 서버 로그에 같은 번호로 남긴다.

## 증거
- 출퇴근 시각은 서버가 요청을 받은 시각이다. 고치거나 지울 수 없고, 잘못 누른 기록은 '실수로 누름'(표시 시각과 이유가 남음)으로 계산에서만 뺀다.
- 위치는 동의한 경우에만 저장한다 (휴대폰에서는 https 주소에서만 된다).
- 올린 자료는 원본 그대로 `data/uploads/<사용자 번호>/`에 고유 이름으로 저장하고, 올린 시각과 SHA-256을 남긴다. `python -m app.evidence_check`로 바뀌지 않았는지 확인한다.
- 게시물은 공개된 것만 검색하고, 주소와 확인 시각, 가능하면 화면 캡처를 보존한다.

## 화면
- **홈**: 출퇴근, AI 에이전트 종합 점검(결과, 확인할 것의 개수, 조언, 에이전트 동작 보기), 종합 점검이 본 기록 목록, 근무 기록, 에이전트 질문, AI 에이전트 진행 상황, 알림. 그만둔 곳은 퇴직 정산과 받았어요/못 받았어요가 종합 점검 카드 안에 있다.
- **급여**: 달별 계산과 받은 금액 비교, 명세서 사진 읽기
- **계약서**: 계약서 사진 읽기, 계약서 내용과 근무 기록을 법 기준표와 대조, 에이전트 동작 기록, 지원 전 확인
- **자료**: 증거 자료, 상담 사전 자료
- **보호**: 신고 후 보호(보복 금지 안내 문구), 게시물 검색과 보존

에이전트를 부르는 버튼을 누르면 그 아래에 일하는 단계가 보이고, 끝날 때까지 그 화면에 머문다. '에이전트 동작 보기'는 입력, 판단, 도구 실행, 결과를 순서대로 보여 주고, 종합 점검은 그 끝에 AI 판단(결과, 이유, 근거 조항, 근거 사실)을 붙인다. 홈의 진행 칸은 한 번에 하나만 뜬다.

알림은 종류마다 최신 것만 남기고, 읽은 지 30일이 지나면 정리한다.

**처음 쓰는 사람 체험 안내**(`FIRST_GUIDE`, 새로 가입한 계정만): 고른 상황과 상관없이 모든 새 계정에 같은 체험 미션 8개(지원 전 확인 → 일할 곳 등록 → 출근·퇴근 → 계약서 사진으로 점검 → 받은 급여 올리고 비교 → 그만둔 곳 등록 → 남은 임금 받았는지 답하기 → 상담 사전 자료)를 서버가 기록으로 판정하고, 업로드 때 예시 자료를 고를 수 있게 하며, 8개를 다 하면 설문(`SURVEY_URL`)을 안내한다 (테스터용).

디자인: 옅은 회색 바탕에 흰 카드, 주 버튼은 검정. 상태는 색 점과 글자로 보인다: 초록 문제 없음, 노랑 확인 필요, 빨강 위반 의심, 파랑 좋고 나쁨이 없는 상태, 회색 아직 안 함.

## 외부 API (없으면 그 기능만 건너뜀)
- 법제처 국가법령정보 (`LAW_OC`): `python -m app.law.fetch`로 근로 관련 법령 7개의 현행 조문과 별표, 최저임금 고시, 판례와 해석을 법 기준표에 저장한다. 매일 자동 점검 때 현행 판이 바뀐 법령만 다시 받는다. 최저임금 금액은 고시를 보고 `data/law_params.json`에 적는다.
- 네이버 검색 (`NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`): 공개 게시물 검색 (연결 코드만 있고, 키를 받지 못해 실제 호출은 확인하지 못함)
- 게시물 화면 캡처 (선택): `pip install playwright && python -m playwright install chromium`

## 시연
- 시험 계정(`TEST_DATA=true`): 방금 가입한 처음 이용자로 시작해 체험 안내를 따라 등록, 출퇴근, 사진 올리기를 보여 준다. 처음 상태로 되돌리기 (서버를 끄고): `.venv/bin/python -m app.demo_db --force` (Windows: `.venv\Scripts\python.exe -m app.demo_db --force`). 가상환경 밖의 파이썬이면 시험 데이터를 지우지 않고 멈춘다
- 알바 5개 사례(위반 의심, 적게 받음, 모두 정상, 정보 부족, 그만두고 못 받음·신고 후 보호)가 든 계정: `.venv/bin/python -m app.demo_db --scenarios --force`
- 급여 탭 **지금 점검**: 월급날을 기다리지 않고 급여 점검
- `POST /api/dev/daily-check`: 매일 자동 점검을 지금 실행 (`DEV_TOOLS=true`일 때만 열림. 매일 점검 자체는 이 설정과 상관없이 돈다)

## 한계
- 임금 계산은 기본급, 주휴수당, 5인 이상 사업장의 야간·연장 가산까지다. 휴일 가산, 연차수당, 퇴직금, 세금과 보험 공제는 계산하지 않는다.
- 실제 AI 모델로 전체 흐름을 끝까지 확인하지 못했다. 시연 전에 `python -m app.llm.probe`와 가상 사용자로 가입부터 상담 자료까지 한 번 돌려 본다.
- 결과는 법적 판단이 아닌 참고용이다.

## 운영 유의사항
개발 규칙은 [CLAUDE.md](CLAUDE.md), 문제 해결은 [docs/실행가이드.md](docs/실행가이드.md) 8절에 있다.
- `.env`는 서버를 켤 때만 읽는다. 고친 뒤에는 다시 켠다.
- 외부에 열 때: `SECRET_KEY` 바꾸기, `--reload` 빼기, 실제 모델 연결, `DEV_TOOLS=false`, 가상 정보만 쓰기.
- cloudflared는 `127.0.0.1`과 `--protocol http2`로 연다. 응답이 100초를 넘으면 Cloudflare가 끊지만, AI 요청은 서버가 뒤에서 실행하고 화면이 결과를 따로 물어 끊기지 않는다.
- 8000번 vLLM은 개발 중에 끄거나 다시 켜지 않는다. 설정을 바꿀 때만 GPU 서버에서 `deploy/stop_vllm.sh`, `deploy/start_vllm.sh`를 쓴다.
- 모든 기록과 파일은 `data/` 아래에 둔다. 예전 코드로 만든 기록도 새 코드에서 동작해야 한다.
